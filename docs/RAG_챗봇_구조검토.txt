검토 대상: C:\BuBot 현재 코드, 지식 색인(storage/knowledge_index.json), 평가·대화 검증 기록

1. 결론
현재 BuBot은 "수치 계산과 지식 검색을 결합한 하이브리드 RAG 대화형 챗봇"입니다.
10/8 오전 검토 때는 벡터 검색이 지역·월 필터로 문서 1개를 고르는 데 그쳐 실질적인 RAG라 보기 약했으나,
현재는 서술형 질문의 답변 근거를 의미 검색이 결정하며, 최근 3개 질문·답변을 기억하는 다중 턴 대화를 지원합니다.
최근 실제 API 평가는 30/30이지만 평가 이후 코드가 바뀌어 재측정이 필요합니다 (evaluations/정확도평가.txt).

2. 현재 처리 구조
[입력 보정] 한/영 전환 없이 친 질문 복원(keyboard.py)
[대화 메모리] 세션별 최근 질문·답변 3개를 서버 메모리에 보관(conversation.py). 후속 질문은 GPT가 단독 질문으로 재구성
[규칙 선처리] 광주 모호성, 연간·기간 평균, 하락 지역, 작년·보유 연도, 개념·정정 질문(period_queries.py, year_query.py, coverage.py)
[질문 분석] GPT 구조화 출력(Pydantic 스키마) → 코드가 지역·기간을 다시 확정(최근 N개월, 질문에 없는 월·상위 지역 제거, 같은 이름 지역 확인)
[수치 경로] 조회·비교·추이·가격 순위: 원본 문서를 ID로 직접 조회 → Python 계산 → 지식 검색으로 지역 프로필·시장 요약·안내 보강
[서술 경로] 흐름 요약·시장 동향·변동률 순위·용어 설명: 지식 색인 벡터 검색 → 검색 문서만 근거로 답변. 거리 0.75 이내 근거가 없으면 GPT 미호출
[답변 검증] 답변 속 변동률(%)을 근거와 대조, 불일치 시 1회 재생성, 그래도 다르면 [수치 확인 필요] 표시(answer_check.py)
[출처] 문서 ID·원본 행·SHA-256을 코드가 생성. 모델 본문 속 출처 문구는 제거(source_display.py)

지식 색인: 454개 문서 (안내 18, 지역 프로필 245, 월별 시장 요약 176, 연도별 시장 요약 15), text-embedding-3-small 1,536차원
2026-10-12 확인: 현재 코드로 생성한 문서와 저장된 색인의 원본 해시·문서 해시·컬렉션 이름이 모두 일치 (embed 재실행 불필요)

3. 10/8 검토 지적 사항 처리 현황
| 지적 사항 | 상태 |
| [높음] 대화 이력 미사용 | 해결: 최근 3턴 메모리, 질문 재구성, 확인 질문 응답 연결 |
| [높음] 질문 해석 검증 부족 | 대부분 해결: 기간·지역을 코드로 재확정. 단 해석 규칙이 rag_service.py에 분산 (7항 참조) |
| [높음] 기간 집계 범위 제한 | 대부분 해결: 기간 평균, N년 하락 지역, 변동률 순위(시장 요약), 역대 최고 시점(지역 프로필) |
| [중간] 벡터 검색 역할이 좁음 | 해결: 지식 색인 의미 검색이 서술형 답변의 근거를 결정 |
| [중간] 근거-답변 자동 대조 없음 | 일부 해결: 변동률(%)만 대조. 금액은 표기가 다양해 미대조 |
| [중간] 검색 품질·추적 부족 | 일부 해결: 검색 문서·거리·단계별 처리 시간 기록. 거리 임계값은 실제 질문으로 미보정 |
| [중간] 평가 재실행 | 10/8 실행(30/30). 이후 변경분은 재실행 필요 |

5. API 키 관리 (의도된 보안 설계)
API 키는 프로젝트 폴더 밖의 C:\keydata\gpt_key.py(open_Aikey)에서 읽습니다. 개인 보안을 위한 의도된 구성입니다.
- gpt_api.py의 API_KEY는 비워 두며, 프로젝트 폴더를 공유·백업해도 키가 함께 나가지 않습니다.
- check-api와 웹 상태 표시는 키 인식 여부만 보여 주고 키 값은 출력하지 않습니다. API 오류 상세도 화면에 보내지 않습니다.
- 다른 경로는 환경변수 BUBOT_KEY_FILE, 또는 OPENAI_API_KEY / BUBOT_API_KEY로 지정할 수 있습니다.
- 우선순위: gpt_api.py API_KEY → OPENAI_API_KEY → BUBOT_API_KEY → 외부 키 파일. 운영 중에는 외부 파일 방식을 유지하세요.

7. 남은 과제와 관찰 사항 (미수정)
- query_parser.py(516줄)는 지역 인식(find_regions)만 사용되고, 기간 해석·의도 판별(parse_question, decide_intent)은 어디서도 호출되지 않습니다.
  rag_service.py에 같은 역할의 규칙이 따로 있습니다. 통합하거나 미사용_보관으로 옮기는 결정이 필요합니다.
- rag_service.py(약 560줄)에 정규식 기반 특수 처리가 계속 늘어나고 있습니다. 새 규칙을 추가하기 전에 해석 단계를 한곳으로 모으는 정리를 권장합니다.
- 월 없이 연도와 "가격/평균"만 적은 질문은 연평균(1~12월 단순 평균)으로 답하고, "각각·차이·비교" 등이 있으면 그 해 마지막 보유 월 값을 씁니다.
  두 규칙이 서로 다른 파일에 있어 질문 표현에 따라 결과 유형이 달라집니다. 의도한 동작인지 확인이 필요합니다.
- 기간 평균 판정이 한 요청에서 두 번 실행됩니다 (성능 영향 작음).
- 지식 검색 거리 임계값(0.75)은 실제 임베딩 질문으로 보정하지 않았습니다.
- 대화 메모리는 웹 서버 프로세스 메모리에 있어 서버 재시작 시 사라집니다 (의도된 동작, 단일 프로세스 전제).

8. 권장 순서
1) 정확도 평가 재실행 (2회 이상) → 결과를 정확도평가.txt에 반영
2) 서술형·다중 턴 질문 평가 세트 추가 (현재 30문항에 미포함)
3) query_parser 통합 여부 결정 및 해석 규칙 정리
4) 거리 임계값 보정 (main.py ask ... --show-retrieval 로 거리 확인)
5) 운영 전환 시 인증·접근 제어·Rate Limit 등 기획서 보안 항목

9. 검토 범위와 한계
코드 읽기, 오프라인 테스트, 가짜 임베딩·모의 GPT로 경로별 재현, 원본 CSV 독립 계산 대조를 수행했습니다.
이번 재검토에서 실제 유료 API는 호출하지 않았습니다. 실제 GPT 해석이 바뀐 결과는 재평가로 확인해야 합니다.
