BuBot - 아파트 평균매매가격 하이브리드 RAG 챗봇
(2026-10-08 RAG 구조 전환 반영)

1. 처리 구조
(대화 메모리) 이전 질문·답변이 있으면 GPT가 현재 질문을 단독 질문으로 재구성 → 아래 처리
질문 → 규칙 확인(광주 모호성, 보유 연도 등) → GPT 질문 분석 → 라우터
  [수치 경로] 가격 조회·비교·추이·가격 순위
    원본 CSV에서 정확한 지역·월 문서를 ID로 직접 조회 → Python 계산
    + 지식 색인 검색(지역 프로필, 같은 월 시장 요약, 관련 안내 문서)으로 보강 → GPT 답변
  [서술 경로] 흐름 요약·시장 동향·변동률 순위·용어/데이터 설명
    지식 색인 벡터 검색 → 검색된 문서만 근거로 GPT 답변
    관련 문서가 거리 임계값 안에 없으면 GPT를 호출하지 않고 "근거 없음" 안내
모든 답변에 근거 문서 ID·원본 행·SHA-256 출처가 붙습니다.

3-1. API 키 (개인 보안을 위한 외부 파일 방식)
키는 프로젝트 폴더 밖 C:\keydata\gpt_key.py 의 open_Aikey 값을 읽습니다. 폴더를 공유·백업해도 키가 포함되지 않도록 한 의도된 구성입니다.
gpt_api.py 의 API_KEY는 비워 두세요. 다른 경로는 환경변수 BUBOT_KEY_FILE 로 지정합니다.
환경변수 OPENAI_API_KEY / BUBOT_API_KEY 도 사용할 수 있습니다.
우선순위: gpt_api.py API_KEY → OPENAI_API_KEY → BUBOT_API_KEY → 외부 키 파일.
check-api·웹 상태는 키 인식 여부만 표시하며 키 값과 API 오류 상세는 출력하지 않습니다.

4. 처음 한 번 / 데이터·안내 문서 변경 후
.\.venv\Scripts\python.exe main.py prepare     (선택) 문서 생성 확인, API 미호출
.\.venv\Scripts\python.exe main.py embed       지식 색인 임베딩 (필수)
embed 비용: 약 450개 문서, 1회 수십만 토큰 수준 (text-embedding-3-small).
같은 본문은 저장된 벡터를 재사용하므로 안내 문서 한 개를 고치면 그 문서만 다시 임베딩합니다.
CSV를 갱신하면 지역 프로필·시장 요약 수치가 바뀌므로 해당 문서들이 다시 임베딩됩니다.
기존 가격 문서 색인(embed-prices)은 제거했습니다. 코드는 미사용_보관/ 에 있습니다.

6. 대화 메모리
세션마다 최근 질문·답변 3개(최소 3개)를 서버 메모리에 기억합니다. 디스크에 저장하지 않습니다.
이어지는 질문 예: "강남구 2026년 8월 가격" → "서초는?" → "그럼 1년 전이랑 비교하면?"
확인 질문 응답 예: "광주 8월 가격" → (어느 광주인지 확인) → "광주광역시"
"동구 8월 가격"처럼 같은 이름 지역은 후보를 보여주며 되묻고, 다음 대답을 원래 질문에 연결합니다.
기억한 내용은 질문 해석(재구성)에만 쓰고, 답변 수치는 매번 원본·지식 색인에서 다시 가져옵니다.
기억 개수: 환경변수 BUBOT_MEMORY_TURNS (기본 3, 3 미만 불가)
유지 시간: BUBOT_MEMORY_TTL_SECONDS (기본 7200초). 서버 재시작·웹 '새 대화'·새로고침 시 초기화.
이어지는 질문에는 재구성 API 호출 1회가 추가됩니다 (첫 질문은 추가 호출 없음).
CLI 대화: .\.venv\Scripts\python.exe main.py chat   (/new 새 대화, exit 종료)

7. 관련도 임계값
bubot/config.py KNOWLEDGE_MAX_DISTANCE (기본 0.75, 코사인 거리)
또는 환경변수 BUBOT_KNOWLEDGE_MAX_DISTANCE.
조건이 확정된 문서(질문한 지역의 프로필, 질문한 월/연도의 시장 요약)는 임계값과 무관하게 사용합니다.
기본값은 실제 질문으로 보정되지 않았습니다. --show-retrieval 로 거리 값을 보고 조정하세요.

8. 데이터 처리 규칙
원본 단위 천원. 결측은 0으로 계산하지 않습니다.
"최근 N개월"은 최신 월 포함 N개월로 코드가 확정합니다 (예: 최신 8월 → 6~8월).
동구·중구처럼 중복된 이름은 시도와 함께 입력해야 합니다.
가격 순위는 비교 범위 전체 유효 데이터에서 계산합니다. (구) 지역 제외.
변동률 순위는 지식 문서(월별·연도별 시장 요약)에 미리 계산된 상위 목록으로 답합니다.
미래 예측, 투자 추천, 전세/월세, 거래량은 지원하지 않습니다.
(2026-10-08 수정) 기간·지역 해석을 코드로 확정하는 규칙
- 연도·월 없이 "요즘·현재·지금·최근"만 있으면 데이터 최신 월. 모델이 고른 과거 월은 쓰지 않습니다.
- 연도만 적고 월이 없을 때: "가격·평균"만 물으면 그 해 1~12월 월평균 가격의 단순 평균(연평균, 결측 월 제외)으로 답합니다.
  "각각·차이·비교"가 있으면 그 해 마지막 보유 월 값, 추이는 전년 12월 ~ 그 해 마지막 월. 질문에 없는 월을 모델이 고르면 무시합니다.
- "최근 N년 평균"은 최신 월 포함 N×12개월 평균입니다 (예: 최근 3년 → 2023-09~2026-08). 변동률·하락 지역 비교는 N년 전 같은 달 기준입니다.
- 줄인 이름(강남 → 강남구)과 상위 지역 수식(포항 남구, 경기 광주)을 인식합니다. 중구·광주처럼 여러 곳에 있는 이름만 적으면 되묻습니다.
- "작년 대비"는 "최근 1년"(같은 달 비교). 작년·올해 등은 명시 연도로 바꿔 처리합니다. '10년'처럼 기간을 뜻하는 숫자는 연도로 보지 않습니다.
- 지역 프로필의 "N개월 전 대비"와 "최근 N개월(최신 월 포함)"은 다른 값이며 둘 다 표시합니다.
- 여러 시도에 있는 이름(중구 등)에 질문에 없는 시도를 모델이 붙이면 후보를 보여 주고 되묻습니다.
- 질문에 없는 상위 지역을 모델이 덧붙이면 뺍니다. 순위의 검색 범위는 질문에 적힌 지역입니다.
- 답변 속 변동률(%)을 근거와 대조합니다. 부호가 반대이거나 근거에 없으면 1회 다시 쓰고, 그래도 다르면 [수치 확인 필요]를 붙입니다.
- 한/영 전환 없이 친 질문(예: tjdnf → 서울)은 한글로 바꿔 해석하고 화면에 표시합니다.

10. 속도
