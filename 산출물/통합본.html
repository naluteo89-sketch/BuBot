BuBot 팀 발표 요약

문서 ID: PR-01 / 버전: 1.0 / 기준일: 2026-10-12 / 약 5분

어떤 문제를 해결하나요

“서울의 월평균 매매가격은 얼마인가”, “두 지역은 얼마나 차이가 나는가” 같은 질문을 자연어로 조회합니다. 표를 직접 찾는 과정을 줄이고 계산과 원본 출처를 함께 확인할 수 있게 하는 것이 목적입니다.

어떻게 답하나요

질문 → 지역·기간 확인 → 원본 계산 또는 지식 검색 → 답변 → 출처 표시 순서입니다. 숫자는 Python 코드가 계산하고 모델은 제공된 근거를 바탕으로 설명합니다. 모호한 지역은 다시 묻고 데이터가 없는 기간은 안내합니다.

현재 구현의 핵심

기능 발표에서 설명할 내용
원본 데이터 245개 지역, 176개월, 2012-01~2026-08
계산 가격·비교·추이·순위, 기간 평균과 하락 지역 조회
설명 근거 안내·지역 프로필·시장 요약 454개 지식 문서

검증 퍼센트 불일치 시 1회 재생성, 지속 시 경고

검증 결과와 남은 일

2026-10-12 자동시험 125건이 모두 통과했습니다. 실제 모델 답변의 현재 정답률은 이번 시험으로 측정하지 않았습니다. 질문 파서의 지역 탐지는 현재 연결되어 축약명과 모호성을 처리합니다. 전체 질문 프레임 통합은 추가 검토 대상입니다.

다음 단계는 팀 요구사항 확인, 실제 API 시연 케이스 검증, 전체 질문 프레임 통합 여부 결정입니다.

시연 순서

  1. “서울 2026년 8월 평균 매매가격”으로 값과 출처를 보여줍니다.
  2. “부산은?”으로 이전 기간이 이어지는지 확인합니다.
  3. “서울 2017년 평균 매매가격”으로 유효 월의 단순 평균을 설명합니다.
  4. “광주 2026년 8월 가격”으로 확인 질문을 보여줍니다.

위 시나리오는 발표용 계획이며 이번 작업에서 실제 API 시연을 완료한 기록은 아닙니다. 현장 시연 전에 MAN 케이스로 결과를 남기세요.

수정과 재생성

프로젝트 루트 C:\BuBot에서 실행합니다.

.\.venv\Scripts\python.exe 산출물\도구\refresh.py

이 명령은 파일 기준표·코드 목록·자동시험 목록·통합 HTML만 갱신합니다. 직접 작성한 요구사항·설계 설명·시험 결과 판정은 덮어쓰지 않습니다. Python과 markdown-it-py가 필요하며 현재 가상환경에서 확인했습니다.

코드가 바뀌면 유지보수_가이드.md에 따라 관련 문서와 시험 결과도 함께 수정하세요. 자동 생성 자료가 최신이어도 요구사항이나 수동 문서가 자동으로 검증되는 것은 아닙니다.

갱신 절차

  1. 변경 목적과 영향받는 REQ ID를 기록한다. ID는 삭제·재사용하지 않고 폐기 상태로 남긴다.
  2. Markdown 문서 원본을 수정한다. 작성일·버전·변경 이력을 함께 적는다.
  3. 자동시험을 실행하고 새 날짜의 로그를 04_시험/실행증적에 저장한다.
  4. 시험 결과서의 건수·실행시간·미실행 항목을 실제 로그와 맞춘다.
  5. 도구/refresh.py를 실행한다. 자동 목록·SHA-256·통합 HTML이 갱신된다.
  6. 발표용_통합본.html에서 검색·표·링크를 확인한다. 업무 기준은 팀 검토자가 확인한다.

기준정보.json은 마지막 생성 시점의 목록이다. 재생성 시 이전 파일은 기준정보_이전.json으로 보관하므로 장기 이력이 필요하면 별도 날짜 폴더에 기준정보와 실행 로그를 복사하거나 Git에 함께 커밋한다. 기존 보관 사본은 비교용이며 원본 소스와 데이터는 갱신 도구가 수정하지 않는다.

사용자 요구사항 정의서

문서 ID: AN-01 / 버전: 1.0 / 기준일: 2026-10-12 / 상태: 현재 구현 기반 팀 검토 초안

목적과 사용자

사용자는 자연어로 지역과 기간을 질문하고 아파트 월평균 매매가격, 비교, 추이와 근거를 확인한다. 담당 개발자는 원본 데이터와 지식 색인을 관리하고 테스트 기록으로 오류를 추적한다. 팀 검토자는 결과가 원본 계산과 일치하는지 판단한다.

조회 대상은 아파트 월평균 매매가격이다. 개별 매물 호가, 개별 실거래 내역, 미래 가격 예측과 투자 추천은 범위에 포함하지 않는다. 현재 로컬 PC 실행을 전제로 하며 회사 전체 공개 서비스의 인증·권한·부하 SLA는 별도 설계 대상이다.

기능 요구사항

우선순위 높음은 핵심 조회 또는 결과 신뢰성에 직접 영향을 주는 항목이다. 구현 확인은 코드에 경로가 있다는 의미이며 실제 자연어 전수 정확성을 의미하지 않는다. 모든 항목의 업무 승인 상태는 팀 검토 대기이다.

정상 흐름과 예외

웹 요청은 형식·크기·Host/Origin을 검사한 뒤 웹 서비스가 질문·단위·세션을 검증한다. 대화 모듈은 이전 요약을 전달하고 ask가 규칙 처리 또는 모델 경로를 선택한다. 일반 모델 경로는 색인 정합성을 먼저 확인한다. 결과에는 답변, facts, sources, 대화 사용량, timings가 포함된다. 웹 서버는 기록 저장 결과와 전체 시간을 추가한다.

색인 누락·불일치는 재구축 안내 대상이다. 지식 검색 결과가 없으면 근거 없음 안내로 종료한다. 답변의 퍼센트 값 불일치는 1회 재생성 후 경고할 수 있다. 이 검사는 모든 문장이나 모든 가격의 사실 검증이 아니다. 외부 API 예외는 웹에서 502, 입력 오류는 400, 처리 중 추가 질문은 429로 응답한다.

경계와 저장소

data/new_prices.csv는 활성 원본이며 data/data.csv를 현재 조회 원본으로 간주하지 않는다. 가격 문서는 43,365개, 지식 문서는 454개이다. 지식 종류는 guide 18, region_profile 245, market_monthly 176, market_annual 15이다. 현재 답변용 지식 색인과 과거의 가격 문서 벡터 색인을 구분해야 한다.

storage/knowledge_index.json은 색인 식별 정보, storage/vectors/vectors.sqlite3는 지식 문서와 벡터 저장소이다. 대화 문맥은 프로세스 메모리에만 존재한다. 별도 테스트 기록은 디스크에 남으므로 새 대화나 서버 재시작이 저장 기록까지 삭제하지는 않는다.

query_parser.find_regions는 year_query.named_region에서 호출되어 지역명 축약·상위 지역 수식·모호성 판정에 사용된다. Mention은 이 경로에서 사용된다. Period·QueryFrame 및 parse_question 전체 라우팅은 현재 운영 호출이 확인되지 않아 부분 연결로 구분한다.

실행 기준

TC는 기존 자동시험에서 확인한 대표 케이스이며 MAN은 별도 수동시험 계획이다. TC의 실제 결과는 2026-10-12 실행 로그에서 해당 시험명이 ok인 것을 확인한 판정이다. 모든 자동시험 125건의 식별자는 자동시험_목록.md를 참조한다. 대표 케이스의 설명은 실제 테스트 소스의 입력과 assertion에 한정한다.

공통 사전조건: C:\BuBot, 프로젝트 가상환경, data/new_prices.csv, tests/rag_fixtures.py. 전체 실행은 .venv/Scripts/python.exe -m unittest discover -s tests -v이다. mock 케이스는 실제 API가 아닌 지정 응답을 이용한다. 단일 재현 시 예를 들어 -m unittest discover -s tests -p test_period_queries.py -v를 사용한다.
