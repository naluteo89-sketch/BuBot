# 인터페이스와 데이터 설계서

문서 ID: DS-03 / 버전: 1.0 / 기준일: 2026-10-12

## HTTP 계약

| 경로 | 메서드 | 입력 | 정상 결과 |
| --- | --- | --- | --- |
| /api/chat | POST | question, session_id, 선택 unit | answer, facts, sources, standalone_question, followup, input_converted, memory_turns, memory_used, timings, route, retrieved, elapsed_seconds, saved, record_id |
| /api/reset | POST | session_id | reset: true |
| /api/status | GET | 없음 | 프로젝트·출처·기간·결측 안내·키 인식 여부·색인 준비 여부 |
| /api/history | GET | 없음 | 최근 최대 100건 records |
| /api/history/export | GET | 없음 | 전체 records |
| /history | GET | 없음 | 기록 HTML |

POST Content-Type은 application/json이다. 본문 크기는 1~16,000바이트, 질문은 공백 제거 후 1~1000자이다. unit은 천원·만원·억원·korean 중 하나이며 생략할 수 있다. session_id는 영숫자·밑줄·하이픈 8~64자이다. 기록 저장 실패 시 record_id가 없고 saved=false와 warning이 포함될 수 있다.

```json
{"question":"서울 2026년 8월 평균 매매가격", "session_id":"demo-session-0001", "unit":"korean"}
```

| HTTP 상태 | 의미 |
| --- | --- |
| 400 | 입력 검증 실패 또는 잘못된 JSON·본문 크기 |
| 403 | 허용되지 않은 Host 또는 Origin |
| 404 | 없는 경로·허용 정적 폴더 밖 요청 |
| 415 | JSON 이외 Content-Type |
| 429 | 다른 질문 처리 중 |
| 502 | 답변 생성 경로의 예외 |
| 503 | 상태·기록 조회 실패 |

## 데이터 계약

CSV는 첫 3행이 헤더이며 4행부터 지역 데이터이다. 첫 열은 ID, 다음 4열은 지역 계층, 이후는 월별 가격이다. 첫 행의 월은 연월 표기, 셋째 행의 단위는 천원이다. read_corpus는 행별 열 수·월 형식과 중복·시간순·단위·지역 ID 및 경로 중복을 검사한다.

| 객체 | 주요 필드 | 활용 |
| --- | --- | --- |
| 월 가격 문서 | id, text, metadata.kind=monthly, region_id, month, missing | 정확한 지역·월 조회 |
| 출처 metadata | source, source_row, source_sha256, region_path | 원본 역추적 |
| 유효 가격 | price_thousand_krw | 천원 단위 계산. 결측 문서에는 값이 없음 |
| 지식 manifest | source_sha256, documents_sha256, embedding, document_count, collection | 원본·본문·모델 변경 감지 |
| 대화 요약 | question, standalone_question, answer, facts, resolved, clarification, error | 답변은 최대 700자 후 생략표시, facts는 기본 6개 |

원본 데이터의 세부 결측 원인은 값 자체만으로 확정할 수 없다. 현재 웹 결측 안내에는 행정구역 개편을 원인으로 표현하는 문구가 있으므로 업무 검토 시 원인 표현의 근거를 확인해야 한다.
