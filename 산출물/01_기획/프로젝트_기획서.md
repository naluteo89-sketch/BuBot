## 1. 추진 배경

아파트 평균 매매가격은 공공데이터로 공개되어 있습니다. 하지만 사용자가 원하는 답을 얻으려면 큰 통계표에서 지역과 월을 직접 찾아야 합니다. 비교나 변동률이 필요하면 직접 계산도 해야 합니다. 지역명이 겹치는 경우(광주, 동구, 중구 등)와 결측 월이 있는 경우에는 잘못 읽을 위험도 큽니다.

일반 대화형 AI에 같은 질문을 하면 그럴듯하지만 근거 없는 수치를 답할 수 있습니다. 이 프로젝트는 자연어로 질문을 받되, 수치는 원본 데이터에서 코드로 계산합니다. 답변에는 계산 근거와 출처를 함께 제공하는 조회 도구를 만듭니다.

## 2. 목표

| 구분 | 목표 |
| --- | --- |
| 사용자 목표 | 지역·기간을 자연어로 물으면 평균 매매가격, 비교, 추이, 순위를 바로 확인한다 |
| 신뢰성 목표 | 답변의 모든 수치는 원본 CSV에서 Python이 계산하고, 근거 문서 ID·원본 행·SHA-256 출처를 붙인다 |
| 안전성 목표 | 모호한 지역이나 데이터가 없는 기간은 추측하지 않고 되묻거나 안내한다 |
| 운영 목표 | 원본·안내 문서가 바뀌면 색인 불일치를 감지하고, 바뀐 문서만 다시 임베딩한다 |

## 3. 범위

**포함**

- 아파트 월평균 매매가격 조회 (지역·월, 연평균, 최근 N개월·N년 평균)
- 두 지역 이상 비교, 기간 추이와 변동률
- 범위 내 가격 순위, 상승·하락 지역 순위
- 시장 흐름 요약, 용어·계산 방법·데이터 설명
- 이어지는 질문(대화 메모리)과 확인 질문
- CLI(`main.py`)와 로컬 웹 화면(`web_main.py`), 질문별 테스트 기록

**제외**

- 미래 가격 예측, 투자 추천
- 전세·월세, 거래량, 개별 매물 호가와 개별 실거래 내역
- 외부 공개 서비스 운영(로그인·권한·암호화 저장소·부하 대응)

## 6. 서비스 구조 (하이브리드 RAG)

2026-10-08에 기존의 가격 문서 벡터 검색 방식을 다음 구조로 바꿉니다. 수치 질문은 정확한 조회로 처리하고, 서술형 질문만 검색으로 처리합니다.

```text
질문 → (이전 대화가 있으면 단독 질문으로 재구성)
     → 규칙 확인: 모호한 지역, 보유 기간, 한/영 오타
     → GPT 질문 분석 → 라우터
        [수치 경로] 가격 조회·비교·추이·가격 순위
            원본 CSV에서 지역·월 문서를 ID로 직접 조회 → Python 계산
            + 지식 색인(지역 프로필·시장 요약) 보강 → GPT 답변
        [서술 경로] 흐름 요약·시장 동향·변동률 순위·용어 설명
            지식 색인 벡터 검색 → 검색 문서만 근거로 GPT 답변
            거리 임계값 안에 근거가 없으면 GPT 호출 없이 "근거 없음" 안내
     → 답변 속 변동률 대조(불일치 시 1회 재작성, 지속 시 [수치 확인 필요])
     → 출처 표시
```

핵심 원칙은 세 가지입니다.

1. **숫자는 코드가 만든다.** GPT는 질문 해석과 문장 작성만 맡습니다. 지식 문서의 수치도 모두 Python이 계산합니다.
2. **기간·지역 해석은 코드가 확정한다.** “최근”, “작년 대비”, 연도만 있는 질문 같은 표현을 코드 규칙으로 고정합니다. 모델이 질문에 없는 월이나 지역을 덧붙이면 무시합니다.
3. **근거 없으면 답하지 않는다.** 검색 근거가 임계값 밖에 있거나 색인이 원본과 맞지 않으면 생성 전에 멈추고 안내합니다.

## 7. 기술 구성

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 언어·실행 | Python 3.12, 프로젝트 가상환경(`.venv`) | 계산·데이터 처리와 API 연동을 한 언어로 처리 |
| 생성 모델 | OpenAI `gpt-4o-mini` (Structured Outputs) | 질문 분석 결과를 정해진 형식으로 받고 비용을 낮춤 |
| 임베딩 | `text-embedding-3-small` (1536차원) | 약 450개 지식 문서 규모에 충분, 1회 색인 비용 수십만 토큰 수준 |
| 벡터 저장 | SQLite + NumPy 코사인 거리 | 외부 DB 없이 로컬 파일 하나로 관리, 같은 본문은 벡터 재사용 |
| 웹 | 표준 라이브러리 HTTP 서버 + 순수 JS 화면 | 설치 부담 없음, 127.0.0.1 전용 |
| 의존성 | `openai`, `numpy`, `pydantic` | 최소 구성 |
| API 키 | 프로젝트 밖 `C:\keydata\gpt_key.py` 또는 환경변수 | 폴더를 공유하거나 git에 올려도 키가 포함되지 않음 |

| 답변 수치 대조 | 높음 | 변동률 불일치 시 재작성·경고 |
| 웹 화면과 테스트 기록 | 보통 | 질문별 TXT·전체기록.html 저장, 처리 시간 표시 |
| 한/영 오타 보정 | 보통 | `tjdnf` → 서울 변환과 변환 여부 표시 |

## 10. 위험과 대응

| 위험 | 영향 | 대응 |
| --- | --- | --- |
| 모델이 수치를 지어내거나 잘못 옮김 | 신뢰성 저하 | 수치는 코드 계산만 사용, 답변 변동률 대조·재작성·경고 |
| 모델이 질문에 없는 월·지역을 고름 | 엉뚱한 기간 답변 | 기간·지역을 코드 규칙으로 확정, 덧붙인 조건 무시 |
| 같은 이름 지역(광주·동구·중구) | 다른 지역 값 답변 | 후보를 보여 주고 되묻기, 다음 대답을 원래 질문에 연결 |
| 원본 갱신 후 색인 불일치 | 오래된 근거 사용 | 해시 기반 검증, 불일치 시 생성 전에 중단 |
| 검색 거리 임계값 미보정 | 근거 누락 또는 무관 근거 | 기본 0.75로 시작, `--show-retrieval`로 실제 질문 보정 |
| API 비용·지연 | 사용 부담 | 저비용 모델, 같은 본문 벡터 재사용, 연결 재사용과 프롬프트 캐시 |
| API 키 유출 | 보안 사고 | 키를 프로젝트 밖 파일에 두고 `.gitignore`에 `gpt_key.py`·`.env` 등록 |

## 11. 성공 기준

- 핵심 조회(가격·비교·추이·순위) 질문에서 답변 수치가 원본 계산과 일치한다.
- 모호한 지역과 보유하지 않은 기간을 임의로 처리하지 않는다.
- 모든 답변에 근거 문서와 원본 출처가 표시된다.
- 유료 API 없이 실행되는 자동시험이 모두 통과한다.
- 실제 API 기반 정확도 평가 결과를 기록으로 남긴다.
